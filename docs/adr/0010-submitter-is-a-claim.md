# Who submitted a result is a recorded claim, not authentication

`fede submit` records who submitted a result (`--by human`, otherwise the agent), and fede refuses a decision submitted without `--by human`. The coordinator runs fede as the same user with the same shell, so fede cannot tell whether the human really answered. The flag catches a coordinator that forgot to ask, because it now has to lie on purpose, and it gives the ledger and the PR body a record of who claimed each decision. Docs and reports call it claimed, never verified. The guard against a dishonest coordinator is downstream: the pull request stays a draft until the human approves the ready packet, and fede never merges (ADR 0009). We rejected dropping the field (it loses the slip check and the record) and real authentication such as a TTY prompt or a hardware-key signature (an agent can fake a TTY and use a cached key, and a hardware touch is too heavy for v1).
